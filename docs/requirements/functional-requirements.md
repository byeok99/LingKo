이 문서는 화면 모양보다 **사용자가 어떤 목적을 달성할 수 있어야 하는지**를 기준으로 작성합니다. 실제 API 경로와 DTO는 API 문서를 기준으로 하며, 요구사항과 코드가 다르면 불일치를 결함으로 취급합니다.

## 2. MVP 목표

LingKo MVP는 한국어 학습자가 다음 핵심 가치를 처음부터 끝까지 경험할 수 있도록 하는 것을 목표로 합니다.

```text
Google 또는 iOS Apple 로그인
→ 추천 또는 직접 입력 문장 선택
→ 발음 기준 확인
→ 음성 녹음
→ 발음 평가
→ 전체·단어 점수와 음절 발음 가이드 확인
→ 기록 저장 및 다시 연습
```

MVP의 성공 여부는 기능 수가 아니라 다음 질문으로 판단합니다.

1. 사용자가 첫 평가를 끝까지 완료할 수 있는가?
2. 평가 결과가 사용자 기록에 정확히 남는가?
3. 실패와 재시도에서 쿼터와 결과가 중복 처리되지 않는가?
4. 사용자가 자신의 데이터를 조회하고 삭제할 수 있는가?
5. 소수 실제 사용자의 반복 사용 여부를 측정할 수 있는가?

## 3. 사용자 유형

| 사용자 | 설명 | MVP 권한 |
|---|---|---|
| 비회원 | 로그인 전 사용자 | 로그인 화면과 필수 약관·정책 확인 |
| 학습자 | Google 또는 Apple 로그인한 일반 사용자 | 문장 선택, 녹음, 평가, 기록, 설정, 탈퇴 |
| 운영자 | 서비스 운영 담당자 | 로그·메트릭 확인, 제한된 운영 작업 수행 |
| 내부 서비스 | Worker 또는 서버 간 호출 주체 | 가이드 생성 등 내부 작업 호출 |

MVP에서는 별도 관리자 웹 콘솔을 필수로 하지 않습니다. 운영 기능은 인증된 내부 API, 클라우드 콘솔, DB 관리 도구를 통해 제한적으로 수행할 수 있습니다.

## 4. 우선순위 정의

| 등급 | 의미 |
|---|---|
| Must | MVP 출시 전 반드시 구현 |
| Should | 초기 베타 중 구현을 권장하나 제한 공개를 막지는 않을 수 있음 |
| Could | 사용자 검증 후 구현 |
| Out | MVP 범위에서 제외 |

## 5. MVP 포함 범위

- Google OAuth 로그인
- iOS native Apple 로그인
- Access Token 기반 인증과 세션 복원
- 추천 문장 조회
- 사용자 직접 문장 입력과 표준 발음 준비
- WAV 녹음과 재녹음
- 발음 평가 요청
- 전체 점수, 세부 점수, 단어 점수, 음절별 발음 가이드 표시
- 입·혀 가이드 이미지 확인
- 평가 결과 사용자별 저장
- 내 연습 기록 조회
- 일일 무료 연습 횟수 조회·차감
- 로그아웃과 회원 탈퇴
- 주요 오류와 재시도 안내

## 6. MVP 제외 범위

다음 기능은 사용자 검증 후 우선순위를 재평가합니다.

- Android·Web Apple 로그인과 Kakao 등 추가 로그인 제공자
- 유료 구독, 결제, 광고
- 친구, 랭킹, 공유, 커뮤니티
- 실시간 음성 스트리밍 평가
- AI 개인 튜터 대화
- 고급 학습 커리큘럼과 자동 추천
- 사용자용 가이드 영상 생성 요청
- 별도 관리자 웹 콘솔
- Push 알림
- 완전한 다국어 UI
- 대규모 트래픽용 S3 직접 업로드·비동기 평가 Worker

마지막 항목은 초기 제한 베타에서는 제외할 수 있지만, 공개 트래픽 증가 전에 전환 기준을 확정해야 합니다.

## 7. 핵심 사용자 시나리오

### 7.1 첫 평가 완료

1. 사용자가 앱을 실행합니다.
2. Google 계정 또는 iOS의 Apple 계정으로 로그인합니다.
3. 추천 문장을 선택하거나 문장을 직접 입력합니다.
4. 앱이 기준 문장과 표준 발음을 표시합니다.
5. 사용자가 마이크 권한을 허용하고 녹음합니다.
6. 앱이 음성 형식과 길이를 검증합니다.
7. 서버가 쿼터를 확인하고 평가를 수행합니다.
8. 앱이 전체·단어 점수를 표시하고 선택한 단어의 음절별 입·혀 가이드를 제공합니다.
9. 평가 결과가 사용자 기록에 저장됩니다.

### 7.2 반복 연습

1. 사용자가 평가 결과에서 단어별 점수를 확인합니다.
2. 단어를 선택해 해당 단어의 음절만 펼친 뒤 입·혀 가이드를 확인합니다.
3. 같은 문장을 다시 녹음합니다.
4. 새 결과가 별도 기록으로 저장됩니다.
5. 사용자는 과거 결과와 현재 결과를 확인할 수 있습니다.

### 7.3 평가 실패와 재시도

1. 평가 요청 중 네트워크 또는 외부 서비스 오류가 발생합니다.
2. 앱은 실패 원인과 재시도 가능 여부를 안내합니다.
3. 시스템 오류로 완료되지 않은 평가는 쿼터 정책에 따라 복구합니다.
4. 동일 요청 재전송 시 평가·차감·저장은 한 번만 처리합니다.

### 7.4 단어 중심 피드백

1. Practice 결과와 Review 기록은 같은 단어→음절 정보 계층을 사용합니다.
2. 단어 점수는 외부 평가 공급자가 기준 문장의 공백 단위와 신뢰할 수 있게 일치한 경우에만 표시합니다.
3. 단어 점수가 없거나 매핑이 일치하지 않으면 `UNAVAILABLE`로 표시하고 전체·세부 점수는 유지합니다.
4. 음절은 개별 점수를 표시하지 않고, 선택한 단어에 속한 발음 가이드 진입점으로만 사용합니다.
5. 단어 점수를 음절에 복제하거나 임의로 분배하지 않습니다.
6. 과거 기록에 단어 점수가 없어도 표준 발음의 공백과 저장된 음절 순서로 단어 그룹을 복원해 가이드를 열 수 있어야 합니다.

## 12. 변경 관리

- 기능 요구사항 변경 시 ID는 재사용하지 않습니다.
- 삭제된 요구사항은 문서에서 제거하지 않고 상태를 `폐기`로 변경합니다.
- API·DB·보안 계약이 바뀌면 관련 문서를 같은 PR에서 갱신합니다.
- 요구사항을 완료한 PR은 해당 ID와 GitHub Issue를 본문에 기록합니다.
