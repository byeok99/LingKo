# ADR-0005 기준 브랜치 단순화

- 상태: 제안
- 날짜: 2026-07-21

## 배경

저장소 기본 브랜치는 `develop`이지만 최근 인증, 기록, 설정, 쿼터, 가이드 작업과 테스트 개선은 `main`에 더 많이 반영되어 있습니다. 두 브랜치가 서로 갈라진 상태에서는 신규 작업의 기준과 릴리스 흐름이 불명확합니다.

## 제안

소규모 프로젝트 단계에서는 `main`을 유일한 통합·릴리스 브랜치로 사용합니다.

```text
main
 ├─ feat/*
 ├─ fix/*
 ├─ test/*
 ├─ docs/*
 └─ chore/*
```

모든 변경은 짧은 기능 브랜치에서 `main`으로 PR을 생성하고 검증 후 squash 또는 merge합니다.

## 대안

`main`을 릴리스, `develop`을 통합 브랜치로 유지하는 Git Flow도 가능합니다. 이 경우 모든 기능 PR은 `develop`만 대상으로 하고 정기적으로 `develop → main` 릴리스 PR을 만들어야 합니다.

## 결과

- 신규 개발자가 최신 기준 브랜치를 쉽게 알 수 있습니다.
- `develop`의 미반영 커밋을 먼저 검토하고 필요한 변경을 `main`에 반영해야 합니다.
- GitHub 기본 브랜치 변경과 보호 규칙 설정은 별도 관리 작업입니다.

## 전환 체크리스트

1. `develop`에만 존재하는 커밋 확인
2. 필요한 변경을 `main`에 병합 또는 cherry-pick
3. CI와 배포 기준을 `main`으로 변경
4. GitHub 기본 브랜치를 `main`으로 변경
5. 열려 있는 PR의 base 변경
6. 충분한 유예 후 `develop` 삭제 또는 읽기 전용 처리
