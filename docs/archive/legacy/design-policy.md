# LingKo Design Policy

## 목적

이 문서는 LingKo의 Flutter 앱 화면, 컴포넌트, 시각 스타일, 상호작용 기준을 정리한 구현 정책이다. 목표는 "한국어 발음 교정 앱"의 성격에 맞는, 집중도 높고 반복 사용에 적합한 인터페이스를 유지하는 것이다.

LingKo는 브라우저 기반 제품이 아니라 iOS/Android Flutter 앱이다. 화면은 설명보다 작업, 장식보다 피드백, 탐색보다 반복 연습을 우선해야 한다.

## 제품 성격

- 대상: 한국어를 배우는 글로벌 사용자
- 핵심 행동: 문장 선택, 표준 발음 확인, 녹음, 평가, 재연습
- UX 우선순위: 빠른 이해, 낮은 인지 부하, 즉시 피드백

## 디자인 원칙

### 1. 학습 도구답게 만든다

- 첫 화면부터 실제 학습이 가능해야 한다.
- 불필요한 소개 문구는 줄인다.
- 사용자가 다음 행동을 바로 알 수 있어야 한다.

### 2. 피드백을 중심에 둔다

- 점수, 취약 글자, 추천 재연습 구간이 항상 명확해야 한다.
- 결과 화면은 단순히 예쁘기보다 읽기 쉬워야 한다.

### 3. 다국어를 전제로 설계한다

- UI 문구는 짧고 명확하게 쓴다.
- 문장 길이가 늘어나도 레이아웃이 깨지지 않아야 한다.
- 영어 기준으로도 레이블과 버튼이 충분히 들어가야 한다.

### 4. 반복 사용에 적합해야 한다

- 자주 쓰는 액션은 같은 위치에 둔다.
- 화면 전환은 예측 가능해야 한다.
- 매번 새로 배우는 조작이 적어야 한다.

### 5. 광고는 흐름을 끊지 않게 다룬다

- 광고는 연습 시작 전 또는 무료 횟수 소진 지점에만 배치한다.
- 결과 확인 직후에는 광고를 강하게 노출하지 않는다.
- 학습 결과와 광고를 같은 시선 레벨에서 경쟁시키지 않는다.

## 브랜드 톤

- 인상: 차분함, 명료함, 신뢰감
- 금지 방향: 과한 게임성, 과장된 마케팅 톤, 복잡한 비주얼 효과
- 감정 톤: 친절하지만 설명적이지 않음

LingKo는 "공부하는 곳"이지 "놀러 오는 곳"이 아니다. 따라서 시각적 흥분보다 작업 집중도를 우선한다.

## Toss Style

LingKo의 시각 언어는 토스앱처럼 읽힌다. 여기서 의미하는 것은 아래와 같다.

- 흰 배경과 연한 블루 계열 포인트
- 넉넉한 여백
- 강한 제목 대비
- 짧고 직접적인 문구
- 카드보다 명료한 섹션 중심 구조
- 아이콘과 숫자가 정보를 빠르게 전달하는 구성

토스 스타일을 적용할 때 지켜야 할 점은 다음과 같다.

- 화면이 가볍고 깨끗해야 한다.
- 정보는 한눈에 들어와야 한다.
- 장식성보다 신뢰감이 중요하다.
- 버튼과 숫자는 충분히 선명해야 한다.
- 설명은 길게 늘어놓지 말고 결과와 행동을 바로 보여준다.

## 레이아웃 정책

### 전체 구조

- 상단에는 현재 화면의 목적이 바로 보이게 한다.
- 본문은 한 번에 한 가지 작업을 하도록 구성한다.
- 정보는 카드보다 구획된 섹션이나 리스트가 더 적합하다.

### 카드 사용 기준

- 반복되는 항목에만 카드 사용
- 문장 목록, 코스 목록, 연습 기록에는 카드 가능
- 화면 전체를 카드로 감싸지 않는다
- 카드 안에 다시 작은 카드 구조를 중첩하지 않는다
- 카드 테두리와 그림자는 아주 약하게만 사용한다

### 패널 사용 기준

- 결과 요약, 발음 점수, 취약 글자, 광고 안내 같은 작은 정보 블록은 패널 형태가 적합하다.
- 패널은 얕고 분명해야 한다.

### 화면 밀도

- 학습 목록 화면은 정보 밀도를 높게 유지한다.
- 연습 화면은 중간 밀도, 결과 화면은 다시 높인다.
- 터치 영역은 충분히 크되 공간을 낭비하지 않는다.

## 타이포그래피

### 기본 원칙

- 화면마다 제목, 본문, 보조 텍스트의 위계를 명확히 구분한다.
- 강조는 크기보다 굵기와 대비로 먼저 표현한다.
- 장문 설명은 최소화하고 줄 수를 짧게 유지한다.

### 텍스트 규칙

- 버튼 라벨은 짧게 쓴다.
- 문장 학습 화면의 핵심 표시는 1~2줄 안에 들어가야 한다.
- 한국어와 영어가 섞여도 줄바꿈이 어색하지 않아야 한다.
- 문자 간격을 과하게 벌리지 않는다.

## 컬러 정책

### 기본 방향

- 기본 배경은 흰색을 사용한다.
- 브랜드 메인은 `#BBD7F2`로 고정한다.
- 강조 색상은 브랜드 메인과 상태 색상만 사용한다.
- 학습 결과는 점수에 따라 색이 달라지되, 과도하게 요란하지 않게 한다.

### 권장 팔레트

- `background`: `#FFFFFF`
- `surface`: `#F7FBFF`
- `brand`: `#BBD7F2`
- `brand-strong`: `#8FB9E1`
- `brand-soft`: `#EAF4FC`
- `text-primary`: `#15324A`
- `text-secondary`: `#5C7286`
- `border`: `#D9E7F3`

### 상태 색상

- 성공: 안정적인 그린 계열
- 주의: 앰버 계열
- 오류: 레드 계열
- 정보: 차분한 블루 계열

### 금지 방향

- 보라색 중심의 단일 팔레트에 치우치지 않는다.
- 강한 채도의 색을 넓은 면적으로 쓰지 않는다.
- 감성적 그라데이션보다 읽기 쉬운 대비를 우선한다.
- 배경 장식이 화면 의미를 방해하면 제거한다.

## 컴포넌트 정책

### 버튼

- 주요 동작은 명확한 텍스트 버튼 또는 아이콘+텍스트 버튼으로 표시한다.
- 되돌리기, 재생, 녹음, 새로고침 같은 기능은 아이콘을 우선 고려한다.
- 동일한 행동은 모든 화면에서 같은 스타일로 유지한다.
- 주 버튼은 브랜드 메인색 기반의 단일 강조 스타일로 유지한다.

### 아이콘

- 범용 아이콘은 일관된 세트로 사용한다.
- 의미가 모호한 아이콘은 툴팁이나 보조 레이블을 붙인다.

### 카드

- 문장 카드, 코스 카드, 연습 기록 카드에 사용한다.
- 카드 자체가 주요 내비게이션이면 클릭 가능 상태가 명확해야 한다.
- 카드 라운드는 과도하게 크지 않게 유지한다.

### 탭과 세그먼트

- 홈, 코스, 기록, 프로필처럼 상시 전환되는 영역은 탭 구조가 적합하다.
- 문장 상세 안의 보기 전환은 세그먼트 컨트롤이 적합하다.

### Flutter 내비게이션

- 상시 전환 영역은 `BottomNavigationBar` 또는 `NavigationBar`를 우선 고려한다.
- 깊이가 있는 상세 화면은 `Navigator` 스택으로 분리한다.
- 로그인, 언어 설정, 연습, 결과는 각각 독립된 라우트로 둔다.
- 모달은 선택이 짧고 단순할 때만 사용한다.

### 입력

- 자유 문장 입력은 가능한 단순하게 유지한다.
- 숫자 입력보다 선택형 설정이 우선이다.
- 표시 언어, 모국어, 난이도는 드롭다운이나 선택 리스트가 적합하다.

### 점수 표시

- 점수는 숫자와 상태를 함께 보여준다.
- 원형 게이지보다 리스트형 세부 점수가 더 중요하다.
- 숫자만 보여주지 말고 어떤 글자가 약한지 바로 연결해야 한다.
- 점수 숫자는 토스처럼 크고 단정하게 보여준다.

## 발음 화면 정책

### 문장 화면

- 원문은 가장 먼저 보인다.
- 표준 발음은 원문보다 작지만 명확해야 한다.
- 재생 버튼은 눈에 띄어야 한다.
- 느리게 듣기와 일반 재생은 분리한다.

### 평가 결과 화면

- 전체 점수
- 문장 전체 피드백
- 글자별 점수
- 취약 글자 재생
- 입/혀 가이드 진입

결과 화면은 요약과 세부를 동시에 제공해야 한다. 처음에는 전체 피드백을 읽고, 다음에는 약한 글자를 눌러 들어가고, 마지막에 다시 연습하는 순서가 자연스러워야 한다.
토스 스타일을 따를 때 결과 화면은 숫자, 요약, 다음 행동이 한 화면에서 바로 보이도록 구성한다.

### 글자 단위 가이드

- 사용자에게 보이는 단위는 글자다.
- 내부 구현은 초성/중성/종성을 재사용할 수 있다.
- 표시명은 글자 단위로 일관되게 유지한다.

## 다국어 정책

### 표시 언어

- 앱 전체 UI는 사용자별 `locale`에 따라 바뀐다.
- 영어를 1차 기준으로 하고, 향후 언어를 추가한다.

### 콘텐츠 언어

- 한국어 원문은 고정이다.
- 번역문과 설명문은 locale별로 분리 관리한다.
- 발음 설명은 단순 번역이 아니라 해당 언어 사용자에게 이해되는 표현으로 다듬는다.

### 레이아웃 대응

- 영어보다 긴 언어를 대비해 라벨은 고정 폭에 의존하지 않는다.
- 버튼은 최소 너비를 두되, 텍스트가 잘리면 다음 줄로 내려갈 수 있어야 한다.
- 한글/영어/중국어가 섞여도 행 간격이 무너지지 않아야 한다.
- Flutter의 `SafeArea`, `Expanded`, `Flexible`, `Wrap`, `ListView`를 우선 사용해 오버플로를 피한다.
- 폰과 태블릿을 지원하되 웹 데스크톱 레이아웃은 만들지 않는다.

## 광고 정책

- 광고는 학습 흐름의 방해물이 아니라 보상 메커니즘이어야 한다.
- 무료 횟수 소진 후에는 광고 시청을 통해 추가 연습권을 받는 흐름을 분명히 보여준다.
- 광고 페이지는 결과 화면보다 더 자극적으로 보이면 안 된다.
- 광고 안내는 짧고 직접적이어야 한다.
- 광고 영역도 전체 톤과 같은 흰색/블루 계열을 유지한다.

## 접근성 정책

- 텍스트 대비는 충분해야 한다.
- 터치 타깃은 작은 아이콘만으로 끝내지 않는다.
- 색상만으로 상태를 전달하지 않는다.
- 점수, 오류, 성공은 색과 텍스트를 같이 보여준다.
- 다국어 사용자를 위해 명확한 용어를 유지한다.

## 디바이스 정책

- iPhone과 Android 폰을 1차 지원 대상으로 둔다.
- 태블릿은 같은 정보 구조를 유지하되 패딩과 목록 밀도만 조정한다.
- 웹 브라우저, 데스크톱 창 크기, 리사이즈 대응은 범위 밖으로 둔다.
- 가로 모드는 필요한 화면만 제한적으로 지원한다.

## 애니메이션 정책

- 상태 전환에만 의미 있는 애니메이션을 사용한다.
- 페이지 진입, 점수 갱신, 연습 완료 같은 이벤트에만 동작을 넣는다.
- 장식용 반복 애니메이션은 최소화한다.
- 사용자에게 피로를 주는 움직임은 제거한다.

## 빈 상태 정책

- 빈 상태는 다음 행동을 바로 안내해야 한다.
- 예: 아직 연습 기록이 없으면 추천 문장으로 이동할 수 있어야 한다.
- 예: 코스가 없으면 다음 추가 예정이라는 정보보다 다른 학습 진입점을 먼저 보여준다.

## 에러 정책

- 에러 메시지는 짧고 구체적으로 쓴다.
- 기술적 예외와 사용자 메시지를 분리한다.
- 실패했을 때도 다음 재시도 행동이 분명해야 한다.

## 화면별 기준

### 홈

- 현재 학습을 바로 시작할 수 있어야 한다.
- 추천 문장과 코스가 우선 노출된다.

### 문장 상세

- 원문, 표준 발음, 설명, 재생, 녹음이 한 화면에 이어져야 한다.

### 결과

- 숫자보다 해석이 먼저다.
- 전체 점수와 글자별 결과를 함께 보여준다.

### 기록

- 목록은 날짜와 점수가 즉시 비교되어야 한다.
- 깊은 상세는 선택적으로 열어본다.

### 프로필

- 언어 설정, 모국어, 목표 레벨, 로그인 상태를 여기서 관리한다.

## 금지 사항

- 랜딩 페이지 같은 마케팅 레이아웃
- 웹 브라우저 기준의 레이아웃 가정
- 데스크톱 다중 패널 우선 설계
- 과한 카드 중첩
- 불필요한 장식 오브젝트
- 한 화면에 너무 많은 행동 버튼 배치
- 점수와 설명의 우선순위 뒤집기
- 문맥 없는 아이콘 남용

## 구현 체크리스트

- 학습 화면에서 가장 중요한 행동이 1초 안에 보이는가
- 다국어 문자열이 길어져도 깨지지 않는가
- 점수와 글자별 피드백이 한 화면에서 연결되는가
- 광고가 학습 결과를 방해하지 않는가
- 모바일에서 녹음과 재생이 사용하기 쉬운가
- 반복 학습 시 같은 작업을 빠르게 다시 실행할 수 있는가

## 우선 적용 범위

1. 홈과 문장 상세 화면
2. 평가 결과 화면
3. 로그인과 언어 설정 화면
4. 기록 화면
5. 광고 안내 화면

## 결론

LingKo의 디자인은 "예쁜 화면"이 아니라 "반복 가능한 학습 도구"를 만드는 쪽으로 가야 한다. 사용자가 문장을 고르고, 듣고, 말하고, 점수를 보고, 다시 시도하는 흐름이 끊기지 않으면 된다.
