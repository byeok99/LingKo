# 보안·개인정보 설계

이 문서는 코드에서 구현하는 신뢰 경계를 설명합니다. 서비스의 법적 고지와 데이터 처리 안내는 [법무 문서](../legal/README.md)를 따릅니다.

## 인증과 세션

소셜 제공자의 token을 서버에서 검증한 뒤 자체 Access/Refresh Token을 발급합니다. 세션은 기기별 `sid`로 구분하며 Refresh Token 원문 대신 SHA-256 해시를 저장합니다. 보호 요청은 JWT 검증과 세션 활성 여부를 함께 확인합니다.

갱신은 세션 행을 잠그고 토큰을 회전합니다. 이전 Refresh Token 재사용을 감지하면 세션을 폐기합니다. 앱은 동시 갱신 요청을 하나로 합치며 로그아웃 후 지연된 응답이 세션을 되살리지 않도록 세션 변경을 구분합니다.

## 동의와 사용자 소유권

필수 약관·개인정보 확인과 문서 버전을 서버에서 검증하고 기록합니다. 앱은 동의 상태 조회나 저장에 실패하면 Home 진입을 허용하지 않는 방식으로 처리합니다.

평가 작업, 학습 기록, 저장 문장은 인증 사용자 기준으로 접근합니다. 업로드 객체 키와 metadata도 작업을 만드는 사용자와 일치해야 합니다.

AI 전송은 별도 고지·명시적 선택을 서버에 기록해야 가능합니다. 최초 업로드 전에 앱에서
AWS S3와 Microsoft Azure AI Speech, 녹음·기준 발음 전송을 설명합니다. Profile에서 철회할
수 있고 서버는 업로드 발급·작업 접수·Worker 외부 평가 직전에 확인합니다. 작업에 동의
이력 ID를 고정하여 철회 뒤 재허용이 과거 작업을 되살리지 않습니다. 이미 검사 후 시작한
전송과 철회는 분산 원자 작업이 아니므로 진행 중 요청의 회수는 보장하지 않습니다.

## 업로드와 외부 처리

비공개 S3에 제한된 Presigned PUT 권한으로 음성을 업로드합니다. WAV 형식과 크기·메타데이터를 검증하며 평가 후 원본 삭제를 시도합니다. 미제출·잔존 객체의 Lifecycle 정리는 S3 설정에 의존하므로 애플리케이션 삭제와 구분합니다.

Azure Speech에는 평가에 필요한 음성과 기준 발음을, 가이드 생성 파이프라인에는 가이드 프레임을 전달합니다. 외부 서비스의 보존·이전 조건은 코드 검증만으로 보장할 수 없습니다.

## 계정 삭제

현재 Access/Refresh Token의 소유자를 재확인합니다. 사용자 S3 prefix의 현재 객체와 버전·delete marker를 먼저 정리하고, 성공한 경우 DB 사용자 데이터와 세션을 삭제합니다. S3 정리가 실패하면 DB 계정을 보존하고 재시도 가능한 오류를 반환합니다. S3와 DB 사이에 분산 원자 트랜잭션이 있다고 가정하지 않습니다.

## 광고와 내부 API

광고 보상은 앱의 시청 완료 이벤트만으로 지급하지 않습니다. 일회성 서버 세션과 Google SSV 서명, 광고 정책 및 provider transaction ID를 검증합니다.

내부 가이드 작업 API는 기본 비활성화하며 내부 토큰, 요청 제한, URL 검증을 적용합니다. 내부 token과 외부 서비스 자격증명은 환경변수로 관리하며 앱이나 저장소에 포함하지 않습니다.

## 응답과 로그

사용자 응답에는 필요한 오류 코드와 메시지만 제공합니다. 토큰, 음성 원문, 비밀값뿐 아니라 사용자 ID와 사용자별 S3 객체 키도 운영 로그에 남기지 않습니다. 내부 작업 식별자와 기술적 오류는 장애 추적에 필요한 범위에서만 기록합니다. API·Worker의 CloudWatch 로그 사본은 미국 동부 리전에서 14일 보관하며 실제 리전·국외 처리 계약은 [개인정보 처리방침](../legal/privacy-policy.ko.md)을 따릅니다. 오류 처리 계약은 [오류 코드](../api/error-codes.md)를 참고합니다.
